# PHASE 直播边框接入

以用户提供的 `边框.html` 为视觉基准，保留原 Canvas 材质、字形、人物穿插、校准标记与 A/B/C 布局。新增的直播数据层使用透明底、细线与原主题色。旧 `index.html` 保留。

## 使用

1. 服务加载新版本后，打开 `http://127.0.0.1:7788/phase-frame.html`。
2. 选择 A/B/C，在制作控制台编辑视觉参数，在“直播接入”中填写房间、下一项、当前模型及弹幕选项。
3. 点击“保存并应用当前布局”。配置按布局分别保存，房间由所有布局共用。保存不会重连弹幕；只有修改房间才重新订阅。
4. 复制后景和前景地址到 OBS 的两个浏览器源，尺寸均为 **1920×1080**。前后景源使用相同布局。
5. 来源从下到上：内容捕获 → 后景浏览器源 → L2D 来源 → 前景浏览器源。前景和后景按实际画布尺寸原位放置。

A 布局地址：
- 后景：`http://127.0.0.1:7788/phase-frame.html?view=program&scene=A&layer=back&clock=wall`
- 前景：`http://127.0.0.1:7788/phase-frame.html?view=program&scene=A&layer=front&clock=wall`

B/C 将地址中的 `scene=A` 改为 `scene=B` 或 `scene=C`。建议在 OBS 分别建立三个场景；控制台切换布局是编辑操作，不自动移动或切换 OBS 来源。`clock=wall` 让分层动画使用共同时间基准。

| 布局 | 内容区域 x/y/宽/高 | 人物参考区域 x/y/宽/高 | 信息策略 |
|---|---|---|---|
| A 内容与角色 | 72 / 132 / 1344 / 756 | 1446 / 292 / 414 / 756 | 默认四条弹幕，话题与音乐 |
| B 专注内容 | 72 / 132 / 1536 / 864 | 1552 / 512 / 344 / 512 | 默认三条弹幕，音色选择临时占用底栏 |
| C 人物与聊天 | 无 | 140 / 28 / 960 / 1004 | 默认八条弹幕，音色选择临时替换聊天区 |

角色区域是参考框，真实 L2D 需在 OBS 调整位置/缩放。输出分层不包含 demo 静态人物；其仅用于制作台预览。C 后景为不透明暗底，不应覆盖在真实 L2D 上方。

## 数据及保存

- 沿用 `ws://127.0.0.1:7789`，前景订阅 `subscribe`、`ncm.subscribe`；后景不订阅。房间是服务端全局状态，旧边框/待机页等客户端仍可能改变它，使用时保持一致。
- 接入 `danmaku/gift/sc`、粉丝牌、舰长等级、内嵌表情/大表情、热度和连接状态。
- 接入 `ncm.playback/offline`：封面、歌名、歌手、暂停状态、播放时间和进度；B 布局将歌曲信息放在底部。
- 接入 `voice.selection` 的搜索、候选、成功、错误和超时状态；保留原音色命令，页面只显示，不在浏览器执行语音命令。
- `GET/POST /api/frame/config` 读取/保存配置；`POST /api/frame/ack` 确认输出版本。数据保存于 `data/frame-config.json`。沿用现有本机控制接口权限策略。
- 输出每秒拉取配置，前景/后景分别确认；控制台显示已确认的层。确认来自浏览器页，不能证明 OBS 正在播出该场景。
- 普通制作页和 `preview=true` 页面不连接直播 WS。测试消息和音色候选仅在当前页显示。
- 自定义导入的本地图片/视频不上传到后端；完整直播使用 OBS 来源。原 PNG/WebM 导出仅含 Canvas 视觉层，不包含新增 DOM 弹幕、歌曲和音色组件。

## 弹幕、心率与频谱（2026-09-28 迭代）

- A/B/C 默认弹幕上限分别为 4/3/8，可在制作台逐布局调整，上限 5/4/10。实际容纳行数会随消息换行变化；超出区域时移除最旧行。专注布局现在也显示普通弹幕。其“临时提示”开关只影响礼物/SC，不影响普通弹幕和音色注册提示。
- 歌曲与下一项已上移，并增大字号。A 在内容下方分列，B 歌曲在底部右侧，C 歌曲位于聊天与话题之间。音色搜索/注册均有阶段事件和局部过渡，低动态系统设置会禁用位移与节拍动画。
- 制作台的“本机采集”区可扫描心率设备，选定手表后启用接收；一台手表只由一个本机采集进程连接。已经实机扫描到 `Instinct apac` 的心率服务，并连续读取真实 BPM。
- 默认桌面播放设备通过 WASAPI loopback 采集，Python 在本机计算 24 个频段，只向页面发送 0–1 的频段数值。切换系统默认设备后采集程序会重新绑定。OBS 前景从同一个 WebSocket 获取数据，后景不订阅。
- 首次部署或更换 Python 环境运行 `powershell -File scripts/setup-phase-telemetry.ps1`；可用 `-Python <python.exe>` 指定 Python 3.12。服务使用 `PHASE_TELEMETRY_PYTHON` 指向对应解释器。依赖装入忽略版本控制的 `data/telemetry/deps`。
- `GET /api/telemetry/state` 返回采集状态；`POST /api/telemetry/scan` 扫描蓝牙；`POST /api/telemetry/config` 保存设备名/地址和两个采集开关。后两者沿用现有本机控制接口权限。配置保存在 `data/telemetry-config.json`。状态只保存配置，不持久化 BPM 或声音。
- 本机配置已设为 `Instinct apac` 并启用心率、桌面音频采集。手表需要处于心率广播模式，数值过期或设备断开后画面隐藏心率/频谱。

## 顶部心率与频谱样式

- A/B 的心率位于顶部横带，C 位于右上标题上方；字号放大，只有心形随实际 BPM 做双拍动效。数据过期或断开即隐藏；系统或画面开启减少动态效果时停用心跳动画。
- 心形使用 [Pixel Icon Library by HackerNoon 的 regular heart SVG](https://github.com/hackernoon/pixel-icon-library/blob/main/icons/SVG/regular/heart.svg)。SVG 轮廓未修改；本项目用 CSS 蒙版应用主题色和节拍动画。图标依据 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 使用，详细记录见 `public/frame/assets/NOTICE.md`；制作台展示来源及许可。
- 频谱仍使用本机计算的 24 个频段，前端改为细基线、低矮的 3 px 像素刻度和少量主题色峰值。数值有快速上升、缓慢回落；静音保持低密度，不新增面板或发光层。
- 浏览器制作台通过本机 HTTP 服务触发蓝牙扫描，不使用 Web Bluetooth。扫描最长等待 20 秒，显示设备列表并优先选中 `Instinct` 心率设备。HTTP 路由缺失、连接失败和超时分别给出可操作提示。
- 当前运行实例若仍返回 `GET /api/telemetry/state` 的 404，表示需加载修复后的服务代码。OBS 正在推流时保持现有进程；停播后重启中继，再确认该接口返回 200 并在制作台完成扫描。
